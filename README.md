# 先生のAI依頼文工房（仮）

**困りごとを選んで、AIへの依頼文をコピーするだけ。**

日本の教員が日常の困りごとを選び、短いフォームに答えると、ChatGPT・Claude・Gemini・Copilot などに貼り付けられる依頼文（プロンプト）を作る静的Webツールです。

- 工房自身はAIを呼び出しません。文章・画像・ファイルも作りません。作るのは「AIへの依頼文」だけです。
- 登録・ログイン・APIキー・課金は不要です。
- 入力内容はブラウザのメモリ内で依頼文に組み立てるだけで、外部へ送信せず、ブラウザのストレージにも保存しません。
- アクセス解析・広告・外部CDN・外部フォントは使っていません（CSPで `connect-src 'none'` を指定）。

## 収録している16系統

| ID | 困りごと | 主な出力（AIへの要求） |
|---|---|---|
| F01 | 授業の流れ・発問を考えたい | 時間配分つき授業展開、発問、想定反応、振り返り |
| F02 | ワークシート・小テストを作りたい | 問題、解答・解説（別紙可）、難易度調整 |
| F03 | 難しい内容を分かりやすくしたい | 学年相応・やさしい日本語の説明、例、比喩、確認問題 |
| F04 | 教材をレベル別にしたい | 同じ目標で段階の違う教材（元教材は工房に入れない） |
| F05 | 学級通信・学年だよりを作りたい | 見出しと本文の通信原稿、写真の仮枠、A4条件 |
| F06 | 保護者向けのお知らせ・メールを作りたい | 文書形式／メール形式の文案、件名 |
| F07 | 教材用イラスト・挿絵を作りたい | 画像生成AI向けの詳細な指示文 |
| F08 | 掲示物・スライド・プリントをデザインしたい | 構成・レイアウト・配色の指示 |
| F09 | 時間割表・当番表・予定表の形を作りたい | 表の雛形（編成・割り当てはしない） |
| F10 | ルーブリック・評価基準の案を作りたい | 評価基準「案」と検討事項（評定は決めない） |
| F11 | 学校行事の計画・司会台本を作りたい | 実施計画、時程、準備物、台本（安全判断は学校に委ねる） |
| F12 | 会議・校務文書を整理したい | 議題、議事録、要約、決定事項と未決事項の区別 |
| F13 | アンケート・Googleフォームの設問を作りたい | 設問・選択肢の表と誘導表現の点検 |
| F14 | ICT操作説明・トラブル対応を頼みたい | 手順、一般的な切り分け（メニュー名を断定させない） |
| F15 | 文書を校正・言い換えたい | 修正版、変更点、要確認箇所 |
| F16 | 自由な困りごとをAIへの依頼文にしたい | 構造化された汎用依頼文 |

### v1.1：時期・学校行事・季節モチーフ・デザインテイスト

F05（学級通信）・F06（保護者文書）・F07（イラスト）・F08（掲示物・スライド）に、任意の追加設定（折りたたみ）を加えました。どれも使わなければ、v1.0 と同じ依頼文になります（`tests/fixtures/v1.0-prompts.json` との一致をテストで確認）。

| 設定 | 内容 | 使うフォーム |
|---|---|---|
| 時期 | 1〜12月＋上旬・中旬・下旬（作成物を使う時期。行事の実施日とは別） | F05〜F08 |
| 学校行事 | 6分類・108件＋学校独自の名称、複数選択、行事ごとの扱い方（事前案内・直前・振り返り・モチーフのみ） | F05〜F08（F06はモチーフのみなし、F07はモチーフとして扱う） |
| 季節モチーフ | 春夏秋冬・季節の行事・学校生活全般＋自由入力。月に合う候補は表示のみで自動選択しない | F05・F07・F08 |
| 季節感の反映 | 文章／デザイン／両方／反映しない（F07はイラストのみ、F06は時候のあいさつ） | F05〜F08 |
| デザインテイスト | 8種類。文体・絵柄とは独立。モノクロ指定時は色に頼らない指示に変換 | F05・F07・F08 |

- 行事に実施月は登録していません。どの月でも、どの行事でも選べます。
- 運動会／体育祭などの表記ゆれは検索で関連付けるだけで、依頼文には選んだ名称だけが入ります。
- 学校での名称を付けると「青葉祭（文化祭）」、独自の行事だけなら「青葉祭（学校独自の行事）」と出力します。
- 行事の実施日・場所・内容・結果、選んでいない行事、季節の自然の様子は、AIに創作させない指示を入れています。

データは `src/data/schoolEvents.js`・`src/data/seasonOptions.js`・`src/data/designStyles.js`、依頼文への変換は `src/prompts/seasonal.js`、画面部品は `src/ui/extraFields.js` です。

### v1.2：Canva AI 向けの依頼文

F05〜F08の「出力の設定」に「依頼文の出力先」（通常のAI向け／Canva AI向け。v1.3で5択に拡張）を追加しました。初期値は通常のAI向けで、通常AI向けの依頼文は v1.1 と同じです（`tests/fixtures/v1.1-prompts.json` との一致をテストで確認）。

- Canva向けは `src/prompts/canvaPrompt.js` の独立した処理で作ります。「完成したデザインを作る」制作指示で、サイズ・形式／掲載する内容／デザイン／制作の条件の順に並びます。
- 入力はそのまま共通で使い、v1.1 の時期・行事・モチーフ・テイストも反映します。
- F06 は「お知らせ文書（紙・配信）」のときだけ選べます。メール・連絡アプリは通常のAI向けです。
- Canva向けのときは、重複する項目（仕上がりの使い方、F08の使うソフトなど）を隠します。値は消さないので、戻すと元どおりです。
- 依頼文は出力先ごとに別々に保持します。切り替えても、もう一方の文章が表示・コピーされることはなく、手で直した文章も残ります。
- 教師向けの注意事項は依頼文に入れず、画面に「コピーされません」として別に表示します。
- 「Canvaを開く」は https://www.canva.com/ を開くだけのリンクです。依頼文をURLに含めたり、自動で送ったりはしません。
- 生成されたデザインで文字や図形を個別に編集できるとは限らないため、依頼文では「可能な限り編集しやすい形で」と指定しています。

### v1.3：出力先を5つに／Canva向けを「通りやすい型」に作り直し

- 出力先（AI・ツール）を「共通（既存どおり）・ChatGPT向け・Gemini向け・Claude向け・Canva向け」の5つにしました。初期値は共通です。
- ChatGPT・Gemini・Claude向けは、現時点では共通と同じ依頼文です（モデル別の最適化を装わないため）。画面にその旨を表示します。
- Canva向けは、入れ子の少ない自然文の型にしました。冒頭で完成デザインを求め、「サイズ・形式 → デザイン → 紙面に入れる内容（固定で入れる文字／記入欄として残す部分／記事本文の材料）→ 文章の書き方 → レイアウト → してほしくないこと」の順に並べます。
- 季節・行事・テイストは「紙面の想定時期は10月下旬です。季節感は控えめにしてください。」「行事名は『青葉祭』を使用してください。文化祭にあたる行事です。」のような文にして組み込みます（テイストの文は `src/data/designStyles.js` の `canva` / `canvaMono`）。
- Canvaでの生成が不安定な場合のヒントは、画面にだけ表示し、依頼文には入れません。

検索では、16フォームに加えて、依頼文フォームでは扱わない困りごと（通知表所見・いじめの判断・時間割の編成・安全の可否など）に対する案内を表示します。

- **C（専用処理）**：時間割の編成、成績集計など → 依頼文だけでは解けないことを案内し、表の雛形（F09）などと区別
- **D（個人・機密情報）**：所見、個別の計画、苦情対応など → 個別の文章は作らず、個人情報を含まない「一般的な観点」の依頼文のみ
- **E（AIに判断させない）**：いじめの判断、評定、安全・医療の判断など → 依頼文を作らず、判断のための確認項目と相談先を表示

## 構成

```
index.html               画面（CSPで外部通信を禁止）
assets/styles.css        スタイル（外部フォントなし）
icons/                   ホーム画面用アイコン（scripts/make_icons.py で生成）
manifest.webmanifest     ホーム画面に追加したときの名前とアイコン
src/app.js               画面の組み立て・ルーティング（#/、#/f/F01、#/about）
src/data/formOptions.js  校種・学年（校種で学年が変わる）、出力条件などの共通選択肢
src/data/taskCatalog.js  16フォームの定義（項目・表示条件・安全の別軸・検索語）
src/data/search.js       困りごと検索（言い換え語、全角半角・カナかなをならす）
src/prompts/buildPrompt.js   検証 → サニタイズ → テンプレート → 共通品質規則 → テキスト化
src/prompts/taskTemplates.js 16系統それぞれの依頼文テンプレート
src/safety/policy.js     個人情報の可能性の警告、C/D/Eの安全案内
src/ui/                  DOM補助（innerHTML不使用）、フォーム部品、コピー処理
tests/unit/              Node標準のテスト（node:test）
tests/e2e/run-e2e.mjs    Playwrightによるブラウザ操作テスト（iPhone 13相当の画面）
```

ビルド不要の ES Modules 構成です。フォームを追加するときは `taskCatalog.js` に定義を足し、`taskTemplates.js` に同じIDのテンプレートを加えます。

### 安全の別軸

調査資料の A〜E 分類は一軸の研究上の分類なので、アプリ内では次の別軸を持たせています。

- `workflow`: `prompt_only` / `reference_needed` / `specialized_computation` / `human_decision_required`
- `sensitivity`: `generic` / `caution` / `sensitive`
- `review`: `normal` / `heightened` / `expert_or_school_authority`

## 動かし方

ES Modules を使うため、`file://` で直接開くと動きません。ローカルでは簡易サーバーで開きます。

```sh
python3 -m http.server 8000
# http://localhost:8000/ を開く
```

## テスト

```sh
npm test                 # ユニットテスト（依存なし）
npm i -D playwright      # 初回のみ
npm run test:e2e         # ブラウザ操作テスト（スクリーンショットは test-results/）
```

## GitHub Pages で公開する

1. このリポジトリを GitHub に push する
2. Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にする
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

`.nojekyll` を置いているので、Jekyll の処理は行われません。

## 注意

- 本ツールは、学校・自治体の生成AI利用ルールへの適合を保証するものではありません。所属機関の規程が優先です。
- 個人情報の警告は簡単な文字パターンによるもので、表示されなくても個人情報が含まれていないとは限りません。
- 困りごとの分類・フォーム設計は、公開資料をもとにした調査（再構築を含む）を参考に整理したもので、需要の実測統計ではありません。
